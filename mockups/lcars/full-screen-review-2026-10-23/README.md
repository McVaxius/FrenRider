# FrenRider LCARS screen review

Twenty source-guided concept sheets cover Main, Mini, every Settings page, profile popups and supporting states. They use fabricated identities and sample state. They are design artwork, not screenshots from a running plugin.

The implemented testing pilot is **3.0.0.3**, published at [`37268c1`](https://github.com/McVaxius/FrenRider/commit/37268c1ad41478c68060c12c7ac8495c5322f408). It restores the saved Krangle action in the real titlebar, revises LCARS glyphs and outlined controls, and fixes selected-page contrast. Game visual acceptance remains pending. All designs are now approved for the repositories in Z:\myrepos.txt; the existing TODO owns the implementation rollout.

Some retained artwork was generated before that correction and still prints 3.0.0.2 or lacks a distinct Krangle titlebar icon. Those strips are historical concepts. The real titlebar registration and saved Krangle callback are [in Plugin.cs](https://github.com/McVaxius/FrenRider/blob/37268c1/FrenRider/Plugin.cs#L427), with [a focused native registration regression](https://github.com/McVaxius/FrenRider/blob/37268c1/FrenRider.Tests/LcarsAppearanceTests.cs#L18).

The final bounded third image pass completed for nine sheets; the current index links those v3 files. Exact edit inputs are at the top of [PROMPTS.md](PROMPTS.md). Retained v2 files are historical. Review any remaining raster mismatch against the source before using it as an implementation requirement.

Regular and Compact retain the same readable body-text size; density changes spacing. Mini is a separate existing window. The ten Settings pages remain Profile, Follow, Combat, Limit Break, Duty / ADS / Exit, Recovery, Automation, Chocobo, Window appearance and UI / About. [The real navigation](https://github.com/McVaxius/FrenRider/blob/37268c1/FrenRider/Windows/ConfigWindow.cs#L316) selects one page at a time. Profile scope browses the editing target independently of the active character.

The third pass removes or repairs specific raster errors: invented Native party, missing Ignore FATEs and Pandora action, clipped alternate Combat insets, clipped Recovery caption, omitted ordinary Desynthesis/Debug, duplicate sidebar highlight, wrong Krangle meaning, wrong remote opener caption and invented Sound volume. Source controls use a party quick-select beside Fren Name; DAD acceptance is Temporary / Off / Permanent. Krangle obfuscates identifying text. UI sounds is one saved, default-muted preference shared by the appearance pane and speaker shortcut.

Several compositions remain proposals beyond the current retained geometry. The published 3.0.0.3 pilot retained the established Mini and warning geometry with shared styles. Current unreleased source adds dedicated LCARS headers, frames and footers while retaining their actions; the artwork remains a composition reference rather than runtime evidence. All popup/state vignettes are independent examples, not simultaneously open windows. Panels labelled reference, alternate state or policy examples are explanatory artwork: do not add them as new product panels. In sheet 10 the expanded list of exit-method choices is explanatory; in sheet 15 the export reference states do not establish a completed export. Sheet 09's compact sidebar crop omits the bottom item; that does not remove UI / About from the real navigation. Sheet 20's artwork does not establish German localization, Hindi shaping, 150% pixel scaling or a target audio-device result.

The actual Settings owner currently gates its page content when no account exists, including global pages; titlebar appearance editors are a separate access path. Closing the AutoDuty warning with X does not acknowledge the conflict: it can reopen while AutoDuty remains enabled. These are retained behavior boundaries, not new behavior promised by the concepts.

Local checks cover native interaction, saved preferences and diagnostic CPU meshes. The diagnostic renderer uses manual Begin and does not draw Dalamud custom-titlebar icons. Its images therefore cannot prove those icon pixels; the registration regression verifies bindings and callbacks separately. Neither diagnostic output nor these concepts establishes game/GPU, live managed-font or audible-device acceptance. No client action is implied by this review pack.
